# 0002: Where the demo's player data comes from

Date: 19 November 2026. Status: proposed, awaiting approval. This is the default taken for the brief's open question on data source (assumption 12).

## Context

The riskiest assumption in the brief is that the user can get real NBA data into a database they own, legally and for free. Phase 1 read the terms (links and dates in `docs/requirements.md` section 4):

* NBA.com, the source behind `nba_api` and the team's sync job: statistics only for news or "private, non-commercial purposes", with attribution; a service featuring a regularly updated statistics database needs consent.
* Sports Reference, scraped by a script in copy 6: no automated access without written permission; no websites or tools built on scraped data.
* balldontlie: a free key exists at 5 requests a minute; reports say game stats need a paid tier; its terms were not found or read.

The prediction needs 20 or more game logs per player (`server/prediction.js:54`).

## Options

| Option | Cost | Risk | Reversibility | When to pick |
|--------|------|------|---------------|--------------|
| A. Sync NBA.com data with `nba_api` into the demo database, as the team did | Low effort, 0 dollars | High: a public, regularly updated stats database is the case the NBA.com terms reserve for consent | Medium: data already published | Only with written consent from the NBA, which is unrealistic |
| B. Static seed in the repo, a small labeled sample (at most 30 players, one past season), from a source whose terms allow display; real NBA.com data loaded only on the user's machine for private study | Medium: a seed script and a terms check | Medium: depends on finding a permitting source; until then the sample is synthetic and labeled | High: swap the seed file | Default for a portfolio demo |
| C. Synthetic players only, generated by a script, clearly labeled as made up | Low | Low legal risk; lower appeal to a reviewer, projections show method not real players | High | If no permitting source is found by 1 December 2026 |
| D. Paid balldontlie tier (9.99 dollars a month) | 120 dollars a year | Medium: terms unread; breaks the 0 dollar ceiling (Q10) | High: cancel | If the user lifts the budget and its terms allow display |
| E. Scrape Sports Reference (copy 6 script) | Low effort | High: forbidden by its data use page | Low | Never |

## Recommendation

**Option B, with C as its starting content.** Commit a seed loader and a labeled synthetic sample now, so the walking skeleton and every acceptance test have data. Replace the sample with real season data only after a source's terms are read and allow display, and record that source here. Keep the `nba_api` path for the user's own machine, never the demo.

What would change this: written terms from balldontlie or another provider that allow free public display, or the user accepting a monthly cost (option D).

## Consequences

The demo shows a "sample data" label until a permitting source is recorded. The success outcome in the brief still holds, because it checks flows, not real players. Phase 2 designs the seed format and loader.
